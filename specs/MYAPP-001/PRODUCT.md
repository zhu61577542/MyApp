# MyApp 第一版产品规格

状态：实施中
日期：2026-09-22
内部编号：MYAPP-001

## 1. 产品目标

MyApp 让同一局域网内最多 3 台电脑共享一套键盘、鼠标和剪贴板。用户通过配置指定一台主电脑，鼠标越过屏幕边缘后开始操作另一台电脑，并能在任意两台已配对电脑之间复制文字、普通文件和文件夹。

第一版支持 Windows、macOS 和 Linux。远程画面不属于第一版；后续加入时默认关闭。

## 2. 目标用户体验

### 2.1 首次使用

1. 用户在每台电脑安装并启动同一个客户端。
2. 用户为设备设置名称，并将其中一台配置为主电脑。
3. 主电脑发现局域网设备，显示一次性配对码。
4. 用户在两端核对并确认配对码。
5. 主电脑用可视化布局设置其他电脑位于本机屏幕的左、右、上或下方。
6. 系统按需提示操作系统权限；用户拒绝时，客户端明确说明受影响功能。

本项目尚无 Figma 设计稿。先实现无界面的核心服务和命令行诊断工具，图形界面在阶段 7 设计和实现。

### 2.2 日常控制

- 鼠标穿过已配置的屏幕边缘时切换目标电脑。
- 键盘输入跟随当前目标电脑。
- 主电脑保留一个本地紧急收回控制动作，该动作不依赖网络。
- 连接断开、应用退出或权限被撤销时，双方释放所有按下状态，鼠标键盘立即回到安全状态。
- 第一版只控制已登录的普通桌面，不控制登录界面、锁屏、Windows UAC 安全桌面或权限更高的应用。

### 2.3 文字复制粘贴

- Windows/Linux 使用 Ctrl+C、Ctrl+V；macOS 保留 Command+C、Command+V。
- 已配对设备间双向同步纯文字。
- 新剪贴板内容带来源设备和版本号，禁止同步回环。
- 用户可以暂停剪贴板同步；暂停后不读取或发送新内容。
- 第一版不承诺富文本、图片或密码管理器私有格式。

### 2.4 文件复制粘贴

- 支持普通文件、多个文件和目录，保留目录层级、空文件和空目录。
- Windows 优先使用虚拟文件流，在资源管理器读取时传输。
- macOS 和 Linux 第一版允许先传入目标端临时缓存，再向系统剪贴板发布真实本地文件 URL。
- 用户能看到准备、传输、校验、完成、失败和取消状态。
- 跨电脑只支持复制，不支持剪切。
- 软件不设置文件大小和数量上限；实际操作受磁盘、文件系统、内存、文件句柄和操作系统限制。
- 目标磁盘不足、源文件变化、名称非法、文件冲突或网络中断时，客户端不得报告成功。
- 符号链接、设备文件、套接字和其他特殊文件第一版拒绝传输。

## 3. 产品不变量

- 总设备数最多 3 台，包含主电脑。
- 同一时刻只有一台主电脑和一个活动控制目标。
- 未配对设备不能发送输入、读取剪贴板或请求文件。
- 所有设备间通信都经过双向认证和加密。
- 设备撤销后，旧证书不能重新连接。
- 输入通道不能被大文件传输阻塞。
- 本地恢复控制不能依赖远端确认。
- 接收端只能在受控目录内创建临时文件，必须拒绝路径越界。
- 未完整接收并校验的文件不得以完成状态暴露给用户。

## 4. 平台范围

| 平台 | 第一版目标 |
|---|---|
| Windows | Windows 10 22H2、Windows 11，x64 |
| macOS | macOS 13 或更新版本，Apple Silicon |
| Linux | Ubuntu 22.04/24.04 与当前 Fedora/KDE 发行版，x64；X11 完整支持，Wayland 按 portal 能力检测 |

Linux Wayland 不保证所有桌面都支持全局快捷键切换。通用交互以屏幕边缘切换为准。

## 5. 非目标

- 第一版不传输远程屏幕、音频或摄像头。
- 不提供公网中继、NAT 穿透或云账户。
- 不控制系统登录、锁屏或安全桌面。
- 不提供跨电脑剪切、剪贴板历史或多主电脑并发控制。
- 不绕过 macOS、Windows 或 Linux 的权限和安全机制。

## 6. 成功标准

- 三台实体电脑连续切换 1 小时，无卡键、失控或错误目标输入。
- 局域网断开后 1 秒内恢复本地控制并释放远端按键状态。
- 中英文输入、常用快捷键、鼠标移动、点击和滚轮通过平台测试矩阵。
- 任意两台设备间文字复制粘贴成功，并且无同步回环。
- 4 GiB 以上文件、十万小文件、空目录、中文文件名和中断恢复通过验证。
- 未配对连接、证书撤销、重放数据、路径越界和损坏数据均被拒绝。
- Windows、macOS、Linux 都能生成可安装、可卸载的软件包。
- macOS 第一版允许直接分发未签名、未公证的 Apple Silicon `.app`，不把 Apple 认证或证书作为发布条件。
- 用户电脑不需要安装开发环境；构建工具运行在 Docker 或专用构建环境中。

## 7. 验证方式

- 单元测试覆盖协议、状态机、配置、身份、路径和数据校验。
- Docker 集成测试覆盖 TLS、断线、限流、大文件和多文件。
- 每个平台执行原生输入、剪贴板、权限和安装包实机测试。
- 三台物理设备执行端到端测试并记录版本、系统、网络和结果。
