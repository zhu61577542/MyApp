# MyApp 第一版技术规格

状态：实施中
日期：2026-09-22
对应产品规格：`PRODUCT.md`

## 1. 技术方向

核心服务使用 Go，实现配置、身份、配对、发现、协议、加密连接、状态机和文件传输。平台原生能力通过按操作系统编译的适配层实现。优先采用纯 Go 和运行时系统 API 绑定，使 Windows、macOS、Linux 核心代码可在 Docker 中交叉编译。

图形界面与核心服务分离。当前 GUI 第一阶段使用标准库 `net/http` 提供本机控制中心：页面内嵌在 Go 二进制中，通过受限本机回环地址访问，不引入新的运行时依赖，也不改变 CLI 和核心服务的生命周期。后续可在保持 `/api` 边界的前提下替换为原生窗口或系统托盘实现。

## 2. 功能模块与实现目录

整体拆分为 14 个模块：

| 编号 | 模块 | 目录 | 职责 |
|---:|---|---|---|
| 1 | 程序入口 | `cmd/myapp` | 启动、诊断、版本、命令行参数 |
| 2 | 应用编排 | `internal/app` | 生命周期、模块装配、关闭顺序 |
| 3 | 配置 | `internal/config` | 配置读取、默认值、校验、迁移 |
| 4 | 设备身份 | `internal/identity` | Ed25519 密钥、证书、设备 ID、安全落盘 |
| 5 | 设备与布局 | `internal/device` | 设备上限、角色、屏幕邻接和活动目标 |
| 6 | 局域网发现 | `internal/discovery` | 签名 UDP 组播、发现过滤、地址变化 |
| 7 | 配对与信任 | `internal/pairing` | 短码确认、证书交换、撤销 |
| 8 | 安全传输 | `internal/transport` | 双向 TLS、重连、心跳、连接优先级 |
| 9 | 应用协议 | `internal/protocol` | 帧格式、消息类型、版本协商、限额 |
| 10 | 输入控制 | `internal/input`、`internal/platform/*/input` | 捕获、切换、注入、按键状态清理 |
| 11 | 剪贴板 | `internal/clipboard`、`internal/platform/*/clipboard` | 文字版本、平台格式、回环抑制 |
| 12 | 文件传输 | `internal/transfer` | 清单、流、校验、缓存、取消、恢复 |
| 13 | 本地存储 | `internal/storage` | 配置、信任库、传输状态和临时文件 |
| 14 | 打包与发布 | `packaging/*`、`build/docker` | 三平台构建、签名、安装、升级 |

只在进入对应阶段时创建源码目录，避免用空目录或占位实现伪装进度。

## 3. 协议

每条控制消息使用固定长度头部和有限长度载荷：

- 4 字节魔数 `MYAP`
- 1 字节协议主版本
- 1 字节协议次版本
- 1 字节消息类型
- 1 字节标志
- 8 字节请求或流 ID
- 4 字节大端载荷长度
- 4 字节头部校验保留位，第一版必须为 0

控制载荷使用 JSON，便于首版调试和兼容扩展；文件内容使用独立二进制流，不把文件编码进 JSON。控制帧默认最大 1 MiB，握手阶段使用更小限制。未知关键消息导致会话关闭，未知非关键消息可按协商规则跳过。

连接分为控制、实时输入和批量传输三类逻辑流。当前 CLI 使用两条独立 TLS/TCP 连接：实时连接承载输入、释放和心跳，批量连接承载文字与文件。两条连接分别认证设备身份，并用 Hello 随机数绑定到同一次会话，拒绝在批量通道注入输入。实时心跳每 100 ms 检查，750 ms 未收到心跳时取消会话；实时收发退出后立即释放按键，不等待批量磁盘任务。后续可在不改变上层协议的情况下评估 QUIC。

## 4. 身份与配对

- 首次启动生成 Ed25519 私钥和自签名设备证书。
- 设备 ID 由公钥 SHA-256 摘要编码得到，不使用设备名或 IP 作为身份。
- 私钥文件仅允许当前用户读取；平台密钥链集成在后续阶段实现。
- 未配对发现使用受大小限制的签名 UDP 组播，只暴露协议版本、设备名称、设备 ID、临时实例 ID、控制端口和配对能力，不暴露剪贴板或文件信息。发现签名防止报文被篡改，但发现到的自签名身份仍不受信任，必须完成短码配对。
- 配对双方基于临时密钥计算人工核对短码，确认后保存对端证书指纹。
- 已建立会话使用双向 TLS，并在应用层校验设备 ID、角色、会话随机数和协议版本。
- 撤销信任立即关闭活动连接并删除可重用会话信息。

## 5. 输入状态机

三机运行时采用主电脑连接两个子电脑的星形结构。控制端配置 `peers`（每项包含 `id`、`address`），数量计入本机并受 `max_devices` 限制。共享一个本地剪贴板同步器，将已接受的子电脑文字和已校验文件转发给另一个子电脑，不向来源回传。文件转发使用独立任务队列，避免在接收回调里递归发送。

在屏幕边缘切换接入前，CLI 提供 Ctrl+Alt+1/2 切换两个目标；切换时先释放旧目标按下状态，Ctrl+Alt+Esc 结束控制并恢复本地。快捷键是过渡入口，不替代边缘切换验收。任一子会话失败时先结束整组会话并释放按键，保留失败原因；自动重连另行接入。

输入状态为 `local`、`entering-remote`、`remote`、`recovering`。只有主电脑可以从 `local` 切换到远端。进入远端前必须确认目标在线和权限可用。断线、超时、权限撤销或紧急键触发 `recovering`，本地立即恢复并向远端发送幂等的“释放全部输入”消息。

鼠标移动允许合并旧事件；按键、按钮和滚轮事件保持顺序。双方维护已按下集合，断线清空。键盘使用物理键码传输，文字输入法兼容性由平台测试确定；跨布局输入可通过文字剪贴板补充。

## 6. 剪贴板与文件

文字条目包含内容哈希、来源设备、单调版本、MIME 类型和时间。客户端只传播本地产生且未见过的版本。

文件复制先发送不可变清单：相对路径、类型、大小、修改时间和内容版本。接收端规范化路径并在受控根目录内打开文件，拒绝绝对路径、`..`、特殊文件和重复路径。传输到临时名称，长度与 SHA-256 校验成功后原子提交。

Windows 适配器提供 OLE 虚拟文件流。macOS/Linux 第一版使用目标缓存并发布本地文件 URL。缓存有引用计数和过期清理，不能在系统仍可能粘贴时提前删除。

## 7. 构建与依赖

- 所有 Go 编译、格式化、测试和代码生成在 Docker 中运行。
- 核心构建使用 `CGO_ENABLED=0`，平台接口优先使用系统调用或运行时动态绑定。
- Windows x64、macOS ARM64、Linux x64 是第一版发布目标；Linux ARM64 保持可编译。
- macOS 第一版分发未签名、未公证的 Apple Silicon `.app`，不依赖 Apple Developer ID。Windows 代码签名仍属于可选发布增强项。
- 依赖必须固定版本并记录许可证；第一阶段除 Go 标准库外不引入运行时依赖。

## 8. 测试策略

- GUI：Docker 内测试首次初始化、重复初始化拒绝、状态读取和配置/身份文件落盘；Docker 内启动服务并通过 HTTP 探测初始化和状态流程。

- 配置：默认值、拒绝未知字段、范围、地址与角色不变量。
- 身份：生成、保存、重载、权限、证书与设备 ID 一致性。
- 协议：分段读写、超限、坏魔数、版本、未知标志、短写和并发流 ID。
- 状态机：三设备上限、角色限制、切换和断线恢复。
- 传输：4 GiB 以上、十万文件、截断、哈希错误、取消、路径越界和磁盘不足。
- 平台：每个平台真实桌面权限、捕获、注入、剪贴板和文件管理器。

## 9. 主要风险

- Wayland portal 支持不一致：运行时能力检测，明确显示不可用原因。
- macOS/Linux 文件粘贴语义不一致：第一版使用目标缓存，保留平台专项原型门槛。
- 权限变化造成失控：恢复动作本地优先，远端释放幂等执行。
- 大文件挤压输入延迟：独立连接和优先级，传输限速可配置。
- 证书或私钥损坏：安全失败，禁止自动生成新身份后静默信任旧设备。
