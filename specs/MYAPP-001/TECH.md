# MyApp 第一版技术规格

状态：实施中
日期：2026-11-23
对应产品规格：`PRODUCT.md`

## 1. 技术方向

核心服务使用 Go，实现配置、身份、配对、发现、协议、加密连接、状态机和文件传输。平台原生能力通过按操作系统编译的适配层实现。优先采用纯 Go 和运行时系统 API 绑定，使 Windows、macOS、Linux 核心代码可在 Docker 中交叉编译。

图形界面与核心服务分离。桌面 GUI 使用 Fyne 原生窗口和系统托盘，入口为 `myapp gui`；窗口关闭时隐藏到托盘，托盘菜单负责重新显示、刷新和退出。原 `myapp gui-web` 仅保留为不依赖图形环境的诊断页面。Fyne 构建在独立 Docker GUI 镜像中完成，核心服务仍使用无 CGO 的 Docker 镜像。

新版桌面交互按 `UX.md` 实施。GUI 专用 `desktop-service` 子进程通过继承的 stdin/stdout 匿名管道交换有界 JSON 命令、操作确认和状态快照，stderr 保留诊断日志；状态流不写入普通日志，避免记录文件路径。stdin EOF 触发安全停止。快照区分配置、进程、TLS 会话、当前控制目标、共享暂停和文件任务，进程代次和请求 ID 防止旧结果覆盖新状态。状态更新合并后输出，不阻塞输入回调；操作确认必须在实际生效后返回。

桌面会话连接后默认保留本机输入。捕获使用独立可取消生命周期，显式开始才启动，结束或紧急退出只停止输入控制。受控端延迟创建原生注入器，缺少输入权限不阻断独立文字/文件共享。协议以可选能力消息协商控制握手和文件结果，旧端未声明能力时禁用对应新操作并提示更新，不将未知结果显示为成功。

桌面键鼠控制要求两端使用新版 GUI；普通 CLI 的自动捕获模式不与 GUI 的显式控制握手混用。未完成控制确认的输入会明确拒绝，不静默丢弃。子电脑暂停接受控制时，实时通道通知主电脑取消本次捕获；文字和文件连接保留。捕获就绪回调确认原生 Hook/Event Tap 已安装后才报告目标生效；Windows 先建立消息队列再安装 Hook。

文件任务以接收端完成长度/哈希校验、原子提交和系统剪贴板发布后的结果为成功依据。结果从批量接收器解耦，通过有界、按任务合并的待发队列发送，避免双向大文件填满各自发送队列后互锁。主电脑中转登记异步文件任务，不在文字中转循环中等待文件完成。文字发送锁与系统剪贴板写锁分开；暂停取消尚在等待的发布并等待屏障。已接纳的文件任务在暂停时可继续，退出则请求双向取消并等待确认；失败或超时只提供明确强退，不伪称已取消。断线结束当前连接的任务上下文，重试使用当前新连接。

布局方向持久化到可选 `Peer.Position`，同目录临时文件、同步和重命名实现配置替换。设置保存重读最新配置，保留后台配对写入的设备。配对确认后在已信任的双向 TLS 中交换真实共享端口，发现报文在配对监听期间公布的是配对入口；不将临时监听端口或客户端源端口存成共享地址。发现失败保留手工 IP 路径，不修改防火墙。登录启动为用户主动启用的 LaunchAgent／用户 Startup 文件，默认关闭；外观与向导偏好单独保存在 `desktop.json`。

## 3. 协议

每条控制消息使用固定长度头部和有限长度载荷：

- 4 字节魔数 `MYAP`
- 1 字节协议主版本
- 1 字节协议次版本
- 1 字节消息类型
- 1 字节标志
- 8 字节请求或流 ID
- 4 字节大端载荷长度
- 4 字节头部校验保留位，第一版必须为 0

控制载荷使用 JSON，便于首版调试和兼容扩展；文件内容使用独立二进制流，不把文件编码进 JSON。控制帧默认最大 1 MiB，握手阶段使用更小限制。未知关键消息导致会话关闭，未知非关键消息可按协商规则跳过。

连接分为控制、实时输入和批量传输三类逻辑流。当前 CLI 使用两条独立 TLS/TCP 连接：实时连接承载输入、释放和心跳，批量连接承载文字与文件。两条连接分别认证设备身份，并用 Hello 随机数绑定到同一次会话，拒绝在批量通道注入输入。实时心跳每 100 ms 检查，750 ms 未收到心跳时取消会话；实时收发退出后立即释放按键，不等待批量磁盘任务。后续可在不改变上层协议的情况下评估 QUIC。

## 4. 身份与配对

- 首次启动生成 Ed25519 私钥和自签名设备证书。
- 设备 ID 由公钥 SHA-256 摘要编码得到，不使用设备名或 IP 作为身份。
- 私钥文件仅允许当前用户读取；平台密钥链集成在后续阶段实现。
- 未配对发现使用受大小限制的签名 UDP 组播，只暴露协议版本、设备名称、设备 ID、临时实例 ID、控制端口和配对能力，不暴露剪贴板或文件信息。发现签名防止报文被篡改，但发现到的自签名身份仍不受信任，必须完成短码配对。
- 配对双方基于临时密钥计算人工核对短码，确认后保存对端证书指纹。
- 已建立会话使用双向 TLS，并在应用层校验设备 ID、角色、会话随机数和协议版本。
- 撤销信任立即关闭活动连接并删除可重用会话信息。

## 5. 输入状态机

三机运行时采用主电脑连接两个子电脑的星形结构。控制端配置 `peers`（每项包含 `id`、`address`），数量计入本机并受 `max_devices` 限制。共享一个本地剪贴板同步器，将已接受的子电脑文字和已校验文件转发给另一个子电脑，不向来源回传。文件转发使用独立任务队列，避免在接收回调里递归发送。

在屏幕边缘切换接入前，CLI 提供 Ctrl+Alt+1/2 切换两个目标。切换时先释放旧目标按下状态，Ctrl+Alt+Esc 结束控制并恢复本地。任一子会话失败时先结束整组会话并释放按键，保留失败原因，再按指数退避重建整组连接。屏幕边缘切换继续单独验收。

输入状态为 `local`、`entering-remote`、`remote`、`recovering`。只有主电脑可以从 `local` 切换到远端。进入远端前必须确认目标在线和权限可用。断线、超时、权限撤销或紧急键触发 `recovering`，本地立即恢复并向远端发送幂等的“释放全部输入”消息。

鼠标移动允许合并旧事件；按键、按钮和滚轮事件保持顺序。双方维护已按下集合，断线清空。键盘使用物理键码传输，文字输入法兼容性由平台测试确定；跨布局输入可通过文字剪贴板补充。

## 6. 剪贴板与文件

文字条目包含内容哈希、来源设备、单调版本、MIME 类型和时间。客户端只传播本地产生且未见过的版本。

Windows 文字和文件剪贴板共用进程内访问锁。每次打开、读写及关闭剪贴板的事务绑定同一系统线程，写入时使用消息窗口作为所有者。外部应用暂时占用剪贴板时，每 10 ms 重试打开，最长等待 500 ms，并响应调用方取消。

文件复制先发送不可变清单：相对路径、类型、大小、修改时间和内容版本。接收端规范化路径并在受控根目录内打开文件，拒绝绝对路径、`..`、特殊文件和重复路径。传输到临时名称，长度与 SHA-256 校验成功后原子提交。接收端在提交前按清单深度从深到浅恢复文件和目录的权限与修改时间，操作通过 `os.Root` 的受控根目录句柄完成，并在每个条目上再次拒绝符号链接和越界路径；目录最后恢复时间，避免子条目创建过程覆盖目录时间。

当前 Windows 使用目标缓存和 CF_HDROP；macOS 使用目标缓存，通过 `NSFilenamesPboardType` 同步发布完整路径列表，并兼容读取本地文件 URL；Linux 发布本地文件 URL。macOS 的短生命周期 `osascript` 使用已写入的路径属性列表，避免 URL 对象发布后退出造成条目丢失；读取 URL 对象时使用原生类数组。OLE 虚拟文件流及缓存引用计数、过期清理仍待接入。

权限清单保存普通 `0777` 位。Unix 按这些位恢复，Windows 通过 Go 的 `Chmod` 将 `0200` 映射为可写或只读属性，实际 ACL 继承目标缓存目录。目录只读属性用于元数据保真，访问控制由 ACL 决定。修改时间单独验证。提交元数据或重命名失败后，临时树按从浅到深的顺序恢复目录 `0700` 和文件 `0600`，以支持重试与取消。进程重启加载状态时也恢复临时权限，保留路径、链接和条目类型校验。

## 7. 构建与依赖

- 所有 Go 编译、格式化、测试和代码生成在 Docker 中运行。
- 核心构建使用 `CGO_ENABLED=0`，平台接口优先使用系统调用或运行时动态绑定。
- Windows x64、macOS ARM64、Linux x64 是第一版发布目标；Linux ARM64 保持可编译。
- macOS 第一版分发未签名、未公证的 Apple Silicon `.app`，不依赖 Apple Developer ID。Windows 代码签名仍属于可选发布增强项。
- 依赖必须固定版本并记录许可证；第一阶段除 Go 标准库外不引入运行时依赖。

日志使用 Go 标准库实现，默认写入用户配置目录下的 `MyApp/logs/myapp.log`，文件权限为 0600。主进程和服务子进程在启动时读取配置中的日志设置；标准输出按 `info` 级别写入，标准错误按 `error` 级别写入。日志流逐行加 RFC3339 时间戳，并对配对码进行脱敏。GUI 导出时复制日志文件，不删除原文件。

## 8. 测试策略

- 历史诊断 Web GUI：Docker 内测试首次初始化、重复初始化拒绝、状态读取和配置/身份文件落盘，并通过 HTTP 探测流程。
- 新版 Fyne GUI：按用户要求不执行 GUI 交互或截图，只编译程序与 GUI 测试源码。2026-11-23 用户另行同意原生光标与实体键鼠探针，记录独立结果。后台覆盖真实命令确认、EOF 停止、显式控制门禁、暂停通知、文件结果/取消与双向并发、撤销后重新配对和配置保存。编译通过不代表视觉、读屏、平台菜单或登录启动实机验收通过。

- 配置：默认值、拒绝未知字段、范围、地址与角色不变量。
- 身份：生成、保存、重载、权限、证书与设备 ID 一致性。
- 协议：分段读写、超限、坏魔数、版本、未知标志、短写和并发流 ID。
- 状态机：三设备上限、角色限制、切换和断线恢复。
- 传输：4 GiB 以上、十万文件、截断、哈希错误、取消、路径越界和磁盘不足。
- 平台：每个平台真实桌面权限、捕获、注入、剪贴板和文件管理器。

## 9. 主要风险

- Wayland portal 支持不一致：运行时能力检测，明确显示不可用原因。
- macOS/Linux 文件粘贴语义不一致：第一版使用目标缓存，保留平台专项原型门槛。
- 权限变化造成失控：恢复动作本地优先，远端释放幂等执行。
- 大文件挤压输入延迟：独立连接和优先级，传输限速可配置。
- 证书或私钥损坏：安全失败，禁止自动生成新身份后静默信任旧设备。

## 10. 当前增强实施约定

Mac 通过 `CGRequestListenEventAccess` / `CGRequestPostEventAccess` 请求授权，通过实际本地网络操作触发系统网络提示；不修改 TCC 数据库。重置仅执行固定的 `tccutil reset All local.myapp.client`，并验证调用来自 MyApp 应用包、先停止所有输入和配对。按 Apple TN3179，macOS 27.2 之前不能重置本地网络授权，不能对该项伪报成功。

配对发现应在打开添加窗口时启动限时监听，监听态仍显示候选设备；选择连接时等待原监听停止，核码时停止广播“可配对”。广播按可用 LAN IPv4 接口发送并设置接口与 TTL；错误进入诊断状态。组播受限时的主动发现只在用户打开添加窗口期间运行，限制本地网段范围和发送频率，回复必须是原有受限、签名、有效期校验的公告。

跨屏使用独立的被动指针监视器，不能为观察屏幕边缘而常开拦截捕获器。主屏几何、边缘比例和往返滞回由可单元测试的状态机处理；进入时沿用 begin/就绪确认/独立捕获生命周期，返回先恢复本机，再等待远端释放确认。几何能力以批量通道上的可选消息协商；旧端缺少该声明时不发送扩展 begin 字段。

光标隐藏按本次捕获租约成对恢复。macOS 使用平衡的 CoreGraphics 隐藏/显示调用；后台服务另动态检测 CGS 的非公开 `SetsCursorInBackground` 连接属性，只在租约内启用，恢复后关闭。该接口不是 Apple 稳定 API，缺失时明确拒绝开始捕获，系统升级需要回归；不用于授予或绕过 TCC 权限。`CGCursorIsVisible` 是已废弃的诊断值，不能独立代替用户对实际外观的验收。

Windows 使用独立看护进程的微小非激活顶层窗口承接源端指针命中并隐藏光标，定时跟随源端位置；标准和自定义光标不依赖替换系统资源。窗口的透明度必须非零，避免系统穿透命中。以实际 `GetCursorInfo` 状态确认就绪；父进程管道关闭时销毁窗口，异常退出由系统回收窗口。不写注册表、不修改系统光标方案。当前应用持有鼠标捕获或无法确认隐藏时拒绝启动。暂停/关闭边缘/编辑布局先阻止新启动，再停止当前捕获；安装前重验状态。恢复失败保留错误并阻止叠加新隐藏租约，普通捕获错误允许修复后重试。

CLI 和桌面控制均把原生回调转交容量 256 的有界队列，回调只做非阻塞投递。单 worker 串行处理，每次输入/切换的锁等待及发送合用 100 ms 期限；Hub 输入信号量支持取消，保留切换与释放顺序。队列满时明确停止捕获，不丢弃按键释放后继续控制；退出先取消并等待 worker，再恢复本机及远端释放。普通捕获失败恢复本机并保留自动切换意图；光标恢复失败则阻止后续捕获。此改动防止网络拥塞阻塞 Windows LLHook，不能据此声称已解释早先两次空白采集。

原生 GUI 及旧发行打包入口均补齐三个权限用途说明；最终 macOS 包核对 bundle ID 和实际 Info.plist，使用本机 ad-hoc 完整性签名，无 Developer ID、无公证。构建检查与原生探针不能替代最终 GUI 授权归属和跨屏体验验收。

### 0.1.7 自动跨屏修正

已信任设备自动结束配对向导并建立服务；旧的 edge_enabled=false、自动连接关闭及150ms停留不再阻断桌面自动跨屏。无系统授权或对端离线时保持安全本机状态，保留自动就绪，使用者解决阻断后无需额外启用。服务启动失败限频重试，配对进程结束前不争用监听端口；可信 peers 变更自动重建连接。位置编辑在保存/取消后恢复此前的自动状态，主动暂停与紧急退出保留。权限预检不发送系统通知，仅展示具体项目；通知去重状态不因刷新、重连或暂停被清空。新授权请求批次为2，升级仅自动尝试一次，不轮询弹出系统授权框。

### 0.1.8 Windows 目标扩展桌面与交接缓冲

通过新的可选非关键 TypeScreenTopology 消息公布实际显示器列表与带负原点的桌面范围，保留原有 TypeScreenInfo 的严格 JSON 结构供旧端使用。布局限制32屏/16KiB，校验范围、标识和规范化布局键，变化时结束旧控制。Windows以PMv2线程上下文枚举物理矩形；目标移动按真实矩形投影，内部接缝不返回主机，空隙不积累不可见位移。Mac源端仍以主屏作为跨机边界。

交接先安装本机捕获并非阻塞入队，目标确认及光标隐藏成功后才打开转发门；预备阶段紧急键仍即时生效。队列满时整体安全退出，不丢弃键盘释放后继续控制。暂停先取消准备态，停止代次防止排队的启动覆盖停止。复用仅加载框架的捕获后端；每次捕获仍独立安装、移除原生Hook。边缘探测4ms、几何和权限复查250ms，降低检测延迟及每事件系统调用；这些不是实测端到端延迟保证。

### 0.1.9 单实例与可诊断跨屏

在GUI初始化和共享服务启动前取得独立的跨版本实例锁，不受配置目录影响。Windows以命名Mutex防重、Event通知已有窗口；macOS/Linux使用用户缓存目录中的flock与受限Unix socket唤起，关闭或进程退出释放锁。Windows托盘使用可被框架解码并转ICO的PNG；保留Mac菜单栏资源。完整拓扑先于旧屏幕消息发送，避免正常初始化被误判为运行中布局变化。源端显示器/指针/远端布局及启动结果独立记录在桌面状态和去重诊断日志中，不记录按键、剪贴板内容或指针坐标。

Mac pbcopy/pbpaste显式使用UTF-8 locale，剪贴板Entry拒绝非法UTF-8；本地非法编码或超出大小限制的纯文本跳过当前修订，不中断键鼠连接。远端哈希校验继续严格执行。原生只读desktop-diagnostics查询当前调用进程的捕获/注入预检和屏幕能力，不安装Hook、不读取剪贴板、不隐藏或移动指针。

实例名从0.1.9起稳定共享；升级时须先退出没有实例锁的旧版本。保护针对当前登录桌面环境，不宣称跨所有OS用户/会话的机器级独占。对等双向控制现已接入，控制权互斥、令牌和恢复屏障见PEER-TECH.md及PEER-STAGE2-TECH.md；实体输入过滤、运行时多屏和速度校准见PEER-STAGE3-TECH.md。0.1.17核心日常体验已获用户认可；固定主副的配置与界面迁移仍待阶段4，完整故障验收仍待阶段5。
