# 2026-11-23 权限、发现与主屏跨机增强验证

本轮实现 Mac 权限请求/重置、配对发现兜底、主屏边缘切换和源端光标恢复，生成 `0.1.6-alpha` 联调预览包。当前不是完整产品验收结论。未执行 GUI 自动化、截图、权限删除或最终应用的系统授权流程；没有第三台实体电脑。

用户已明确选择“接受已记录的 alpha 边界，提交并推送”，包括保留前两次空白采集的未确定原因；不将此选择写成完整验收通过。

## 范围与实现

- Windows 联调通道已恢复并完成任务往返；文件、程序、测试、临时及配置目录均在 `E:\test`。未修改防火墙、网络类别或代理配置。
- Mac 自动请求输入监控/控制键鼠，并尝试触发本地网络登记；最终授权仍需系统提示确认。重置固定为 MyApp bundle 的 TCC 授权，停止共享/配对后才执行，界面明确保留本地网络登记。此次未实际重置已有授权。
- 添加电脑窗口自动限时监听，监听中保留附近电脑列表；连接前停止原监听，核码时停止可配对广播。LAN 接口显式用于组播；新增有界、验签、有时效的单播查询，仍需双方确认短码。
- 主电脑明确启用主屏跨机切换，支持四方向、比例落点、反向返回、停留延迟、防重入及几何变化停止。通过可选屏幕能力消息兼容旧端。
- 源端光标按捕获租约隐藏/恢复。Windows 看护进程使用微小非激活窗口，不替换系统光标方案；父进程异常退出后也恢复。Mac 使用平衡的 CG 隐藏/显示及动态检测的非公开后台连接属性；该接口不用于授予 TCC，系统升级可能失效，需回归。
- 原生回调非阻塞入有界队列，后台串行处理，单事件锁等待及发送共享 100 ms 期限。拥塞停止捕获；取消后等待后台结束，再恢复光标、释放远端输入。暂停和禁用跨屏先阻止排队的新启动。普通启动错误允许重试，恢复状态不确定时阻止新隐藏租约。

### 失败记录及处理

1. 098、099 两轮实体捕获就绪后未收到输入，45 秒超时；用户确认实际操作过。106 加入只计数诊断后通过。计数诊断没有改变过滤规则，因此这两次空白的原因仍未确定，不能标记为已定位并修复。另有静态确认的 Hook 同步等待网络风险，已用队列与可取消锁修复并通过确定性后台测试；没有证据证明它就是上述两次失败的原因。
2. Windows 双向文件测试最初命中内部 10 秒期限。110 记录两端接收约 84%、错误为空且无断线。仅该测试期限调整为 30 秒，111 在约 12.24 秒完成，112 全部 app 测试通过。每方向 256 个块逐块同步落盘可能贡献开销，但尚未隔离存储、安全扫描和协议调度各自耗时。未改变产品心跳/恢复时限或文件持久性实现。
3. 112 的后台测试及正常光标恢复通过；异常退出后，脚本立即读取仍由短暂存活看护进程持有的 stderr 文件，导致任务整体 exit 1。113 等待文件释放后重新执行异常退出检查，确认父进程 exit 23、光标恢复可见及包校验成功。不能把 112 的整体任务记录写成成功。

## 系统行为参考

- [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)：本地网络登记、尽力触发提示、无通用权限查询及当前系统重置限制。
- [Apple CGDisplayHideCursor](https://developer.apple.com/documentation/coregraphics/cgdisplayhidecursor(_:))：隐藏计数及多数情况下的前台限制。
- [Input Leap 官方后台光标实现](https://github.com/input-leap/input-leap/blob/master/src/lib/platform/OSXScreen.mm)：后台连接属性的使用先例，不构成 Apple 稳定性保证。
- [Microsoft LowLevelMouseProc](https://learn.microsoft.com/windows/win32/winmsg/lowlevelmouseproc)：Hook 超时可能静默移除，应快速转交后台处理。
