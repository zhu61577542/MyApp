## 已接入的行为

- 设备、传输、权限与安全、设置四页；系统明暗与可选浅深色、系统字体、平台菜单与设置入口、托盘摘要。
- 首次命名/用途/权限/配对向导，局域网发现与 IP 兜底，真实配对码、对端名称和期限；关窗后保留后台配对。
- 通过匿名管道读取真实进程、会话、目标和任务状态；设备详情展示地址、系统、软件版本与身份信息，不伪造在线状态。
- 连接建立后保留本机键鼠；显式开始控制，等待原生捕获就绪。停止、紧急键与子电脑暂停接受控制均结束捕获，不改变文字/文件偏好。
- 文字、文件、接受控制的运行时开关与暂停确认；设置保存与重连，失败反馈及偏好回滚；配置保存保留后台新配对设备。
- 布局拖动与方向按钮、保存/取消；当前仍以控制期间的快捷键切换目标，未接入屏幕边缘自动切换。
- 文件的准备、接收进度、校验、剪贴板发布、结果确认、双向取消和重新发送；只有接收端成功提交并发布后才显示完成。
- 撤销时先等待未完成配对结束，再关闭会话、撤销本地信任，防止配对完成回写覆盖撤销；退出先停止新共享、释放输入、请求取消任务并等待确认，失败或超时才由用户明确选择强制退出。
- 用户主动启用的登录启动、去重的问题通知、日志导出位置确认；本轮没有启用任何系统登录项。

## 审查后修复的问题

1. 双向大文件发送填满各自队列时，接收器同步回写结果会互相等待。改为有界合并结果队列和独立发送生命周期。
2. 文字发布持系统剪贴板写锁等待队列，可能阻塞远端更新及文件确认。分离发布锁，暂停取消等待中的发布，并让文件中转异步登记任务。
3. 子电脑断线后旧任务重试捕获了服务级上下文。将上下文限定到本次连接，旧连接不能继续登记有效任务。
4. 配对监听端口或客户端临时源端口不能作为共享服务地址。双端确认后通过已信任的 TLS 交换实际共享端口。
5. 子电脑暂停与主电脑开始控制并发时，停止通知可能先于捕获实例创建。增加按对端记录的停止代次，拒绝已失效的启动。

全部 Go 工具均在 Docker 中执行，没有在宿主机安装 Go，也没有运行 Python。

新增后台测试还覆盖：状态管道 EOF 停止、暂停确认后退出、显式注入门禁、旧绑定不覆盖新绑定、停止准备等待任务确认、断线状态清理、配对后实际端口交换、撤销后只能在明确确认下重新配对、非法端口拒绝，以及启动期间对端停止时不安装本机捕获。

## 设计一致性与已确认的边界

检查了 `PRODUCT.md`、`TECH.md`、`UX.md` 和 `IMPLEMENTATION.md`。用户明确选择接受并已同步到设计的两项差异：

| 原设计 | 当前已接受的行为 |
|---|---|
| Windows 托盘单击开窗、右击开菜单 | Fyne 单击、右击均开菜单，菜单提供“打开 MyApp” |
| 撤销时移除双向连接配置 | 本地关闭会话、移除连接配置并撤销信任；旧证书不能再连接，离线对端可能保留无效记录 |

桌面键鼠控制要求两端使用新版 GUI，不与普通 CLI 自动捕获模式混用；未声明桌面能力时提示实际模式边界。旧端没有文件结果确认时标为“已发送，未获对端确认”，不显示完成。
