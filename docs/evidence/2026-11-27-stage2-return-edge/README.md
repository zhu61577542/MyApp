# 第二阶段错位显示器返程修复

2026-11-27 开始排查，跨午夜继续交付。用户确认：Mac 鼠标进入 Windows 后，在显示器 1 左上附近触到左边缘会返回 Mac；显示器 2 位于显示器 1 左侧。

读取 Windows 原生物理布局：主屏为 (0,0) 2560×1440，左侧竖屏为 (-1080,-493) 1080×1920。派生证据 diagnosis.json 仅保留显示器几何、运行进程及日志范围，不保留探针读取的单次光标位置。

代码缺陷：Travel.Move 按光标所在行/列重新求返程边界，因此左侧竖屏上方突出部分的右边缘、主屏下方突出部分的左边缘等凹口也能触发返回。使用相同物理布局的回归在修复前失败，见 before-fix.log。现改为只在目标整组桌面的对应最外侧边界返回；内部接缝和凹口继续投影到实际显示器，空白区域不积累不可见位移。旧测试将凹口返回视为正常，其断言已按修正后的交互要求更新。

验证覆盖左右两个入口、靠近主屏上下角的接缝往返、四方向凹口和四方向最外侧返回。受影响包 race/vet 通过，GUI 编译与检查记录另存。测试不捕获或注入用户实体键鼠。

程序日志缺少逐次返回原因，因此几何缺陷已复现不等于每次用户动作都已归因。新原生 GUI 包交付后，仍需用户验证显示器 1 左上附近不误返、可进入显示器 2 以及正常外边缘返程。第二阶段尚未验收，第三阶段未开始。
