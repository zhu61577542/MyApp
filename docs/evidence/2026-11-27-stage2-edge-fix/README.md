# 第二阶段触边回归修复

用户实际报告：Mac触边令两端从已连接变为已配对/离线，没有完成跨屏；Windows本机鼠标触边无动作但连接保持。用户确认Mac输入监控原未授权，重新添加后原版本仍不能跨屏。

根因：Watcher.Entry保存来源ScreenKey，新peer入口遗漏旧路径的目标标识转换，目标ScreenWithKey因此拒绝，Windows日志显示7次布局变化；准备错误又被当作致命会话错误，导致EOF与离线。新增两端不同屏幕标识的startAt→Link→Driver集成测试，在修复前复现、修复后通过，见before-fix.log与after-fix.log。

修正内容：复制并映射目标ScreenKey，保留来源返程几何；捕获器惰性创建，避免旧工厂权限预检缓存；可恢复的准备/激活/注入错误按令牌传播具体原因并结束本次控制，TLS继续保留；真实网络和OS恢复失败仍拒绝控制并关闭会话。首次恢复失败锁存，自动Close空释放不能绕过；新代次清除旧错误展示。增加对等控制阶段日志。

回归覆盖：准备失败后重试、注入失败仍保持连接、旧错误不影响新租约、碰撞排队新赢家不保留旧诊断、首次恢复失败不能被自动重试清除，以及不同屏幕标识触边。全量race/vet和GUI编译检查通过，见final-checks.log。

Windows反向触边未开放的原因是agent未注册runEdges，属于阶段3既定边界。本次不跳过阶段3过滤、实体接管和源端多屏外边界，不将Windows无触边动作标为已修复。第三阶段尚未开始。
