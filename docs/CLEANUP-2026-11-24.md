# 本机项目清理与双向验证准备

用户明确授权删除本地旧版本程序和无用临时内容。范围限定MyApp项目及可明确归属的构建缓存，不清理其他项目、Docker业务容器或Git历史。

## 清理结果

- 删除484个旧构建/临时文件，逻辑大小1,061,101,265字节，分配空间1,064,513,536字节（约0.99GiB）。包括0.1.9以前的本地.app/ZIP/裸二进制、旧联调探针代码、临时测试程序、重复包、预览副本和失效对象文件。
- 项目专用Go编译缓存从约2.4GiB清空至12KiB；清理后验证仅重新生成当前需要的缓存，约375MiB起。保留模块依赖和工具链，后续不必重新下载。
- 按明确ID清理三个macOS SDK缓存记录及其一个派生零字节层，Docker累计报告933.9+657+656.9=2247.8MB。首个COPY层因派生层引用未立刻回收，补充精确选择派生层后已回收。未使用全局prune。
- 项目磁盘占用从约1.7GiB降至约695MiB；work从约1.3GiB降至约370MiB。本机可用空间从约18GiB升至约23GiB（df显示取整，实际释放空间不直接等同各缓存逻辑大小之和）。

## 保留与核对

- 当前运行的0.1.9 .app、Mac/Windows最新版ZIP和SHA256SUMS保留原路径：work/single-instance-validation。两个ZIP的SHA-256与交付记录一致，Mac严格签名校验通过。
- 配置、偏好、身份和信任文件内容校验前后一致。未触及这些数据；日志与文件缓存由正在运行的程序自行管理。
- 保留一份MacOSX15.2.sdk、Zig压缩包、编译包装脚本和Windows图标资源描述，仍在work/desktop-ui-validation。它们是后续原生构建输入，并非旧版程序。
- 保留通用Windows临时桥的bootstrap/server/token及空任务目录；删除旧任务、载荷与临时探针。本轮未连接或清理Windows电脑。
- 常用Applications/Desktop/Downloads入口未发现其他以MyApp命名的副本。
- 正式代码仍有调用和测试用途；没有以“较旧”为由删除业务模块。源码清理限定临时探针代码，以及误入版本控制的两个fyne临时图标和一个空工具链锁文件。

.gitignore补充生成缓存目录，.dockerignore补充索引、fyne输出和日志排除，避免这些产物以后进入版本控制或构建上下文。既有work/dist排除保留。

## 验证

清理后在Docker执行全量go test -race -timeout=60s ./...、go vet ./...，GUI仅编译及限定的资源/重复实例入口测试，均通过。新增app.Link顺序双向控制后台探针及app包全量race/vet也通过，没有GUI自动化或实际键鼠捕获。当前程序仍可运行，原程序包未改动，无须重新安装。
