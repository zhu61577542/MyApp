# 0.1.8-alpha Windows 多显示器与跨屏交接修复

用户人工反馈：Mac 主电脑进入 Windows 子电脑时卡顿，且无法进入 Windows 显示器2。本轮保留信任后自动跨屏，不增加控制按钮或启用步骤。所有 Windows 软件、包、测试与临时数据限定 E:\test；不执行 GUI 自动化。

## 原因与修复

代码确认：此前只公布目标主屏几何，主端把远程绝对坐标限制在该矩形内，导致 Windows 扩展屏无法进入。现在额外公布实际显示器拓扑，保留旧 ScreenInfo 严格 JSON 和可选非关键消息的兼容路径。Windows 使用 PMv2 线程上下文枚举实际矩形；主端按全桌面计算移动并投影到真实显示器，内部接缝不返回 Mac，错位空隙不积累不可见位移。目标初始落点使用同一投影规则，布局变化停止旧控制。

交接路径此前等待目标确认后才安装源端捕获，确认期间的运动没有进入转发队列；此外逐事件检查屏幕及权限增加系统调用。本轮先准备原生捕获，缓冲运动和键盘事件，目标确认与光标隐藏成功后再按序发送。紧急键在准备阶段即可退出；溢出整体停止，不遗漏按键释放后继续控制。暂停取消准备态，停止代次防止启动覆盖停止。复用捕获后端的框架加载，每次仍独立安装/卸载 Hook。

边缘探测间隔从20ms调到4ms；几何与注入权限检查限为每250ms一次，暂停和拒绝接受控制仍逐事件检查。这些是实现间隔，不是实际端到端性能测量。Mac 源端跨机边界仍为主屏；本轮新增的是 Windows 目标全部扩展显示器支持。

## 实际布局与网络

Windows 只读系统查询及最终程序的 pointer-probe 一致：

| 屏幕 | 原点 | 尺寸 |
|---|---|---|
| 主屏 | (0, 0) | 2560 × 1440 |
| 显示器2 | (-1080, -493) | 1080 × 1920 |
| 全桌面范围 | (-1080, -493) | 3640 × 1933 |

显示器2在主屏左侧并向上错位493像素，不能按“两块水平等高屏”处理。若 Windows 电脑位于 Mac 的右侧，进入 Windows 桌面左边缘时可能先落在显示器2；Windows 两屏内部接缝不是返回 Mac 的边界。

Windows→Mac 四次原生 ICMP RTT 为102、6、12、12ms；随后独立四次为10、15、9、9ms。它提示本轮网络存在延迟波动，但不是实际输入流延迟，也不能证明是卡顿的唯一原因。Mac→Windows 四次 ICMP 没收到回复，不据此认定 TCP 丢包或修改防火墙。

显示器枚举依据：[EnumDisplayMonitors](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumdisplaymonitors)。Windows 原有 SendInput 路径已使用虚拟桌面坐标，本轮修复上游协商与坐标限制。

## 验证结果

证据目录：docs/evidence/2026-11-24-multidisplay。

- Docker 全量 go test -race -timeout=60s ./...、go vet ./... 通过；GUI 仅执行 gui/ci 标签编译检查与 vet，没有运行界面流程。
- Windows pointer 模块交叉 vet 通过；未声称全量 Windows 平台 vet 无告警，旧原生 Hook 回调仍有既存 unsafe.Pointer 检查告警。
- 新增测试覆盖真实负原点、竖屏、错位空隙、主屏与屏2双向接缝、外侧返回、稳定拓扑键及非法布局；net.Pipe 测试覆盖可选拓扑协商与控制键，旧 ScreenInfo JSON 不新增字段。
- 交接测试覆盖原生捕获先于目标请求、确认前缓冲运动及键盘顺序、确认前紧急退出、准备中停止、隐藏失败恢复，以及100个输入事件不重复查询几何、过期后检测布局变化。
- Mac 原生 cmd/pointer 后台测试通过。双端 CGO GUI 编译成功；Mac SDK 构建存在头文件可用性告警，不影响此次构建结果。
- Windows 最终任务121 exit 0、无超时、无 stderr：cmd/pointer/app 后台测试通过，最终 MyApp.exe 的 version 为0.1.8-alpha，原生只读探针确认上述两屏布局。任务120为补充落点校正前的通过记录，最终包以121为准。
- Windows 校验包 SHA-256 后解压，并以替身验证启动脚本的 E:\test 路径约束及旧信任配置复用，未启动 GUI。未执行真实鼠标注入、隐藏或捕获测试。
- Mac .app 完成本机 ad-hoc 签名与 codesign --verify --deep --strict，无 Developer ID、无公证。授权请求批次升为3，升级仅自动尝试一次，最终由系统确认；本轮没有操作 TCC 重置或发起真实授权。

| Windows x64 | f5b9bab3bb69f1f311db70ff99f1e3eb1401b7681c500163223392392abc3972 |

Mac 应用与 ZIP 在 work/multidisplay-validation/。Windows 已保存 ZIP 并解压到 E:\test\MyApp-0.1.8-alpha-multi\app；使用其中 Launch-in-E-test.ps1 启动，会优先复用0.1.7、其次0.1.6目录下已有的信任配置，不删除这些数据目录。两端均退出旧版本再更新，才能使用新拓扑能力。

尚需人工确认：直接越过 Mac 边缘时是否连续、键盘是否跟随；Windows 主屏与左侧竖屏能否往返；从外侧边缘回 Mac 是否恢复指针；暂停与紧急退出是否恢复本机。本轮后台验证证明机制和真实布局读取，未量测物理端到端交接延迟，不能宣称已经达到“无感”。之前接受的 Mac 非公开后台光标接口、历史两次空白捕获原因未定等 alpha 边界继续见上一轮报告。

任务完成后 Windows 临时客户端确认退出，Mac 文件传送监听已关闭，本轮开发容器已停止。
