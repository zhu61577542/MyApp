## 请与我核对这些场景

| 场景 | 应有行为 | 后台结果 |
|---|---|---|
| Mac发起 | 来源和目标都确认就绪后，才能接受Mac输入 | 通过 |
| Windows发起 | 同样能成为来源，不因旧主副配置被拒绝 | 通过 |
| 准备期同时申请 | 按稳定设备标识裁决一个来源，旧准备先撤销恢复；生效后的控制不被普通申请抢占 | 通过 |
| 接收端本地接管 | 旧输入立即失效；本机恢复不等待远端；再次跨屏仍需双方恢复确认 | 通过 |
| 紧急退出/暂停 | 当前控制失效；恢复开关不重放旧申请，需要新的触边动作 | 通过 |
| 断线/单方不续租 | 旧控制失效，迟到续租不能复活；重连必须使用新会话并保留暂停与恢复屏障 | 状态机通过；真实重连在阶段2验收 |
| 迟到/重复消息 | 旧确认、输入、恢复回调不能影响新代次；重复释放无副作用 | 通过 |
| 取消申请 | 取消先到也能阻止迟到申请；旧取消不停止新控制 | 通过 |

“稳定设备标识”是认证身份，不是Mac永远优先。准备期未完成双方就绪时才裁决冲突；已经生效的控制需通过明确接管动作撤销。

本机先恢复可用与允许再次跨屏是两个独立条件：前者不能依赖远端网络，后者必须确认上次输入已释放。若实际释放失败，后续阶段的原生运行时不得虚假报告恢复成功。
